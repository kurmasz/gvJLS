Running JLS

JLS is contained in a JAR (Java ARchive) file. It can be run from a command line, or, depending on the operating system and window manager, by clicking on an icon. It runs in one of two modes: interactive (with GUI) or batch (no GUI). Interactive is the default. Use the -b flag (see below) to run JLS in batch mode.

When run in the interactive mode, JLS will create a checkpoint file after every 10 changes. The name of the checkpoint file is the name of the circuit with ".jls~" appended. If JLS aborts and you are not able to save the circuit you are working on, then you can recover the checkpointed state by renaming the checkpoint file (delete the "~") and starting JLS again.

Command Line Execution

The basic command for starting JLS in interactive mode is: 

    java -jar jls-<version>.jar
This starts up JLS with no circuit in the editor. The user can subsequently create a new circuit or open an existing circuit.

If a circuit file name is specified on the command line then JLS will start up with the circuit already loaded in the editor, e.g. 

    java -jar jls-<version>.jar circuit.jls
To run JLS in batch mode type 
    java -jar jls-<version>.jar -b circuit.jls

(note that a circuit file must be specified when -b is used)

Icon Startup

The mechanism for starting JLS by clicking on an icon is dependent on the particular operating system and window manager. While the details differ, most allow the icon to be parameterized in such a way as to allow the various command line options to be specified.

Flags

-b Batch mode.

-d time Set the simulation time limit, a positive integer, e.g., -d 1000.

-h Print a short help message.

-i [imagefile] Export an image of the circuit then exit (no GUI). By default, JLS draws only the top-level circuit and names the image after the circuit file: adder16.jls produces adder16.png. To choose the file name, provide it after the flag, either attached (-iadder.png) or as the next argument (-i adder.png). The name must end in .png, .jpg, .jpeg, or .svg, which sets the format. JLS uses the ending to tell the image name from the circuit file. To draw subcircuits instead of the top level, add -circuit.

-circuit pattern (or -circuits pattern) With -i, draw the subcircuits that match pattern instead of the top level (see Subcircuit Names and Patterns). You may repeat the flag; JLS draws each subcircuit that matches any of the patterns, once. A single match is drawn alone, like the top level. Several matches are stacked top to bottom in one image, in the order -list-subcircuits prints them, each captioned with its path (the top level with the circuit's name).

Unless you give -i a file name, JLS names the image after what it draws. For the circuit adder16.jls (shown under Subcircuit Names and Patterns), the default names are:

  • adder16.png for the top level alone;
  • adder16-bit0.png for one subcircuit, such as group0.bit0;
  • adder16-circuits.png for several stacked subcircuits.
A single subcircuit's image is named after the subcircuit itself, not its path. Two different subcircuits with the same name therefore get the same file name, and the second image replaces the first. To keep both, provide -i a file name.

For example:

  • -i -circuit group0.bit0 adder16.jls draws one 1-bit adder and saves it as adder16-bit0.png.
  • -i fulladder.png -circuit group0.bit0 adder16.jls saves the same drawing as fulladder.png.
  • -i -circuit . -circuit group0 -circuit group0.bit0 adder16.jls draws one circuit from each level—the 16-bit adder, a 4-bit group, and a 1-bit adder—stacked in adder16-circuits.png.
  • -i -circuit bit0 adder16.jls is a common mistake: bit0 has no dot, so it matches all four bit0s, and JLS stacks four copies of the same drawing in adder16-circuits.png.

-list-subcircuits [pattern] Print the circuit's subcircuits as a tree and exit (no GUI). Use it to find the paths to give to -circuit. With a pattern, it prints only the matching subcircuits and the subcircuits that contain them, so you can check a pattern before giving it to -circuit. (The top line always prints, whether or not the pattern selects the top level.) It cannot be combined with -b, -i, -export, -savetext, -p, or -v.

-s file Read JLS start-up file before loading any circuits, e.g., -s parameters.

-t file Read JLS test input file just before simulating a circuit, e.g., -t inputsigs. The file will be read every time the simulator is started, so changes made to the file will affect a subsequent simulation run.

-pprinter When used with batch mode causes the entire circuit to be printed. If a printer name is present, the output will be sent to it.

-vprinter When used with batch mode causes the top level of the circuit to be printed (no subcircuits). If a printer name is present, the output will be sent to it.

-rprinter Forces batch mode, runs the simulator, and prints the signal trace to the named printer.

-vcd file When used with batch mode, writes the value-change history of all watched signals to the named file in industry-standard VCD format (IEEE 1364), viewable in waveform viewers such as GTKWave or Surfer. The exact format, and the rest of the batch input/output contract, is specified in docs/batch-interface.md in the source distribution.

-export file Export the circuit as Verilog-2005 or VHDL and exit. The file's extension chooses the language: .v for Verilog, .vhd or .vhdl for VHDL.

-board name and -pins file Use these two flags together with -export to also write a pin-constraint file (.pcf) for the named FPGA board. The pins file says which board pin each port connects to. Each line has the form port pin, or port[bit] pin for one bit of a multi-bit port. Lines starting with # are comments.

-savetext file Save a copy of the circuit to the named .jls file as plain, uncompressed text, and exit.

Any flag that takes a value accepts it attached (-d10000) or as the next argument (-d 10000). An argument of -- ends the flags, so a file name after it may begin with -.

Subcircuit Names and Patterns

-circuit and -list-subcircuits identify a subcircuit by its path: the names of the subcircuits that contain it, then its own name, separated by dots. For example, here is the output of -list-subcircuits for a 16-bit adder, adder16.jls, built from four 4-bit adders (group0 to group3), each built from four 1-bit adders (bit0 to bit3): 

    . (adder16)
    |-- group0
    |   |-- bit0
    |   |-- bit1
    |   |-- bit2
    |   `-- bit3
    |-- group1
    |   |-- bit0
    |   |-- bit1
    |   |-- bit2
    |   `-- bit3
    |-- group2
    |   |-- bit0
    |   |-- bit1
    |   |-- bit2
    |   `-- bit3
    `-- group3
        |-- bit0
        |-- bit1
        |-- bit2
        `-- bit3
The first line, ., represents the top level. Every group is an instance of the same 4-bit adder, so the names inside the groups repeat: there are four subcircuits named bit0. Their paths distinguish them: group0.bit0, group1.bit0, etc.

The argument to -circuit and -list-subcircuits is a pattern. A full path, such as group2.bit0, selects one subcircuit. A name with no dot, such as bit0, selects that name wherever it appears. Wildcards select more: * matches any characters (or none) within a name, so group* matches all four groups. Only ** matches across a dot. The table shows what some patterns select in adder16.jls.

PatternMeaningSelects in adder16.jls
bit0 A name without a dot matches that name at any depth. group0.bit0, group1.bit0, group2.bit0, and group3.bit0
group2.bit0 A pattern with a dot must match the whole path, starting at the top level. only group2.bit0
. The top level. the top level
group2.* Everything directly inside group2. group2.bit0 through group2.bit3
* A name without a dot matches at any depth, so * matches every subcircuit. all 20 subcircuits, but not the top level
** The top level and every subcircuit. all 21 circuits: the top level and its 20 subcircuits

** also works inside a path, where it matches any number of levels: group2.** selects everything inside group2, however deep.

Within a name you can also use ? (exactly one character), [0-3] (one character from a set), [!0] (one character not in the set), and {group0,group3} (any one of the alternatives).

A pattern must match a whole name, including case: group does not match group0, and neither does Group0. Only . and ** select the top level.

Put quotes around patterns. Otherwise the command shell may treat them as file-name wildcards and expand them before JLS sees them. For example: 

    java -jar jls-<version>.jar -i -circuits '**' adder16.jls
    java -jar jls-<version>.jar -list-subcircuits 'group2.*' adder16.jls
The first command draws the top level and all 20 subcircuits, stacked in adder16-circuits.png. The second lists the four bits inside group2. These examples use single quotes, which work on macOS, Linux, and in PowerShell. In the Windows Command Prompt, use double quotes instead: "**".
